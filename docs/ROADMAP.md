### 已知问题（按严重程度）
1. **教练仍然下不过 AI（最重要）**：象棋 AI 没有静态搜索（quiescence），叶子节点直接静态评估，存在严重的水平线效应——深度 6 的教练看不到“下一步被吃子”，推荐的走法常常是送子。国际象棋 `ChessAI.js` 有 quiescence，所以那边正常。
2. 评估函数不检查“子被攻击/被保护”，也没有机动性、子力联动评估，开局之后几乎只剩棋子价值 + 位置表。
3. 搜索实现缺陷：置换表只按 depth 缓存，没有区分精确值/上下界（alpha-beta 下会返回错误分数）；超时返回的是未完成的评估；`cloneGame` 每个节点都走 FEN 序列化，很慢；搜索跑在主线程，深度 6 会卡死界面。
4. **读档后悔棋失效**：`loadGameState` 只恢复了 `state.history` 和棋盘，`game.history`/`moveHistory` 是空的，读档后点“悔棋”会清空走法记录且无法回退。
5. **“REST API” 需求未落地**：之前要求用 REST API 保存进度，目前只用了 localStorage，后端仍然只有 WebSocket，没有任何 HTTP 接口；国际象棋对局也没有自动存档。
6. 象棋缺少**长将/长捉、重复局面和棋、60 回合无吃子**等规则；`in_stalemate` 在象棋里应判负（无子可动者输），目前显示“和棋”。
7. 象棋没有接入联机、对局历史、排行榜、每日残局；走法记录是 `炮b2-e2` 坐标式，不是传统纵线记谱（炮二平五）。
8. 工程：只有一个空壳 `App.test.js`，没有任何规则/AI 测试；README 仍然是最初的“Stockfish + 聊天室”；React 17 / react-scripts 4（GitHub 提示 43 个依赖漏洞）。

## 2. 下一步计划

### P0 — 让教练真正能带赢（1–2 天）
- [ ] 给 `XiangqiAI.js` 加 **quiescence search**：叶子节点只继续搜索吃子/将军，直到局面平静。
- [ ] 评估函数加入“被攻击且无保护的子”惩罚、将军/被将军、车炮控制线的简单加分。
- [ ] 修复置换表：key 带上 depth + 节点类型（exact/lower/upper）；超时的结果不写入缓存；用迭代加深（深度 1→N）保证超时也能返回上一层完整结果。
- [ ] 走法排序：置换表最佳着法 → 吃子（MVV-LVA）→ 杀手着法/历史启发。
- [ ] 把 AI/教练搜索放进 **Web Worker**，界面不卡，并显示“教练思考中…”。
- [ ] 验证方法：写一个脚本让“教练(深度 6) 的建议”对战“AI 深度 2”各 50 局，目标胜率 ≥ 90%；这个数字作为回归指标。

### P1 — 存档、REST API、稳定性（2–3 天）
- [ ] 修复读档后的悔棋：读档时用 `moveHistory` 逐步重放走法，或把 `history`（含每步前棋盘）一并序列化。
- [ ] 后端增加 REST 接口（`backend/app.js` 里加 Express，与 WebSocket 共用端口）：
  - `GET/PUT /api/games/:id` 读写对局（FEN、走法列表、模式、难度、颜色）
  - `GET /api/games?user=` 列出进行中的对局
  - `POST /api/games` 新建；`DELETE /api/games/:id`
  - 前端：登录用户走 REST（或 Firebase），未登录回退 localStorage。
- [ ] 路由扩展：`#/xiangqi/ai`、`#/xiangqi/coach`、`#/xiangqi/tutorial/3`、`#/game/:id`（可分享的对局链接）、`#/chess/puzzles/:id`。
- [ ] 国际象棋 `ChessGame.js` 同样接入自动存档和路由。
- [ ] 象棋补全规则：长将禁止、重复局面、无子可动判负、自然限着。

### P2 — 功能补齐（3–5 天）
- [ ] 象棋接入联机对战、对局历史、排行榜（复用 `Multiplayer.js` / `GameHistory.js` / `Leaderboard.js`，走法协议加 `variant: 'xiangqi'`）。
- [ ] 传统记谱（炮二平五、马八进七）和走法列表点击回放。
- [ ] 象棋复盘模式（对每一步给出“失误/妙手”评级），复用国际象棋 Retrospect 的思路。
- [ ] 象棋每日残局 / 经典残局谱（七星聚会、蚯蚓降龙等），教程扩充到 20 课（含开局、杀法、残局）。
- [ ] 扩充开局库：顺炮、列炮、屏风马、反宫马、飞相局的前 6–8 回合，用 FEN 序列索引。

## 3. 建议顺序

```
P0 quiescence + 评估 + Worker  →  胜率回归脚本验证
        ↓
P1 读档悔棋修复 + REST 存档 + 路由扩展
        ↓
P2 联机/历史/排行榜 → 记谱 → 复盘 → 残局
        ↓
P3 测试与文档随每个阶段同步补，不要最后再补
```
